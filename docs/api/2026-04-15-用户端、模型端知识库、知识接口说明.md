# 用户端、模型端知识库、知识三方系统接口说明

本文档面向**外部系统 / 集成方**，说明与知识库浏览、知识条目查询及**无登录模型检索**相关的 HTTP 接口。实现以当前 WeKnora 服务为准。

---

## 1. 通用约定

| 项 | 说明 |
|----|------|
| 协议 | HTTPS（生产环境推荐） |
| 数据格式 | 请求与响应均为 **JSON**（GET 无 Body 时除外） |
| 路径前缀 | 下文路径均相对于部署根路径，完整形态为 `{部署域名}/api/v1/...` |
| 示例域名 | 若对接环境为知识中台测试域，可替换为：`https://zsk.t.nxin.com` |

### 1.1 认证方式概览

| 接口 | 认证方式                                                                                                                                                                      |
|------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 知识库列表、知识搜索 | **用户态**：`Authorization: Bearer <JWT>`；或（租户侧已配置时）`X-API-Key: <租户 API Key>` ;或（`cas cookie`）_cas_t_sid=swcY_-OBaNfymZWsic2YjyOCvpD7ybV0DEvV; _cas_t_uid=12351580551822472317; |
| 开放知识检索 | **非用户登录**：`X-Open-Retrieve-Api-Key`（由服务方配置发放，与用户租户 `X-API-Key` 不同）                                                                                                        |

### 1.2 建议请求头

- `Content-Type: application/json`（POST 且带 Body 时必填）
- `X-Request-ID: <唯一 ID>`（可选，便于联调与日志关联）

### 1.3 错误与状态码

常见情况：`401` 未认证或 Token/API Key 无效；`403` 无权限；`400` 参数错误；`500` 服务端异常。具体 `error` 字段以响应 JSON 为准。

## 2. 知识库列表

用于获取**当前身份**可见的知识库（含个人库及按策略可见的共享库等）。

| 项 | 内容 |
|----|------|
| 方法 | `GET` |
| 路径 | `/api/v1/knowledge-bases/user` |
| 完整示例 | `GET https://zsk.t.nxin.com/api/v1/knowledge-bases/user?include_shared=true` |

### 2.1 查询参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `include_shared` | 布尔字符串 | 否 | 是否包含共享知识库；默认 **`true`**。传 `false` 可仅看非共享策略下的列表 |

### 2.2 请求头

- `cookie`:_cas_t_sid=swcY_-OBaNfymZWsic2YjyOCvpD7ybV0DEvV; _cas_t_uid=12351580551822472317;  ```Authorization: Bearer <JWT>` **或** `X-API-Key: <租户 API Key>`  

### 2.3 成功响应（要点）

HTTP `200`，Body 示例结构：

```json
{
  "success": true,
  "data": [
    {
      "id": "知识库ID",
      "name": "名称",
      "type": "知识库类型",
      "visibility": "可见性",
      "tenant_id": 1,
      "knowledge_count": 0,
      "chunk_count": 0,
      "is_owner": true,
      "member_role": "成员角色（共享库等场景）",
      "created_at": "RFC3339",
      "updated_at": "RFC3339"
    }
  ]
}
```

字段以实际部署版本为准；`data` 为数组。

### 2.4 调用示例

```bash
curl -sS -G "https://zsk.t.nxin.com/api/v1/knowledge-bases/user" \
  --data-urlencode "include_shared=true" \
  -H "Authorization: Bearer YOUR_JWT"
```

## 3. 知识列表（搜索）

在当前用户（或 API Key 对应租户上下文）可见范围内，按关键词等条件分页检索**知识条目**。

| 项 | 内容 |
|----|------|
| 方法 | `GET` |
| 路径 | `/api/v1/knowledge/search` |
| 完整示例 | `GET https://zsk.t.nxin.com/api/v1/knowledge/search?keyword=&offset=0&limit=20` |

### 3.1 查询参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `keyword` | string | 否 | 关键词；可为空 |
| `offset` | int | 否 | 分页偏移，默认 `0` |
| `limit` | int | 否 | 每页条数，默认 **`20`** |
| `file_types` | string | 否 | 扩展名过滤，逗号分隔，如 `pdf,txt,csv` |
| `agent_id` | string | 否 | 若填写，则在**共享智能体**所配置的知识库范围内检索（需对该智能体有访问权限）；不传则按默认用户可见范围 |

### 3.2 请求头

- `Authorization: Bearer <JWT>` **或** `X-API-Key: <租户 API Key>`

### 3.3 成功响应（要点）

HTTP `200`：

```json
{
  "success": true,
  "data": [],
  "has_more": false
}
```

- `data`：知识条目列表（结构随业务模型扩展，以实际返回为准）
- `has_more`：是否还有下一页

### 3.4 调用示例

```bash
curl -sS -G "https://zsk.t.nxin.com/api/v1/knowledge/search" \
  --data-urlencode "keyword=" \
  --data-urlencode "offset=0" \
  --data-urlencode "limit=20" \
  -H "Authorization: Bearer YOUR_JWT"
```

## 4. 模型知识检索（开放检索，无用户登录）

供**外部模型或自动化服务**在**不持有用户 JWT** 的情况下，按已知的知识库 ID 和/或知识 ID 拉取与问题相关的分片内容。  
**不做用户维度的资源归属校验**；安全边界由服务方配置的 **开放检索专用 Key** 与部署策略保证。对接前需由服务方开启 `open_retrieve` 并下发 Key。

| 项 | 内容 |
|----|------|
| 方法 | **`POST` only**（不支持 GET） |
| 路径 | `/api/v1/open/knowledge/retrieve` |
| 完整示例 | `POST https://zsk.t.nxin.com/api/v1/open/knowledge/retrieve` |

### 4.1 请求头（必填）

| 头 | 说明 |
|----|------|
| `Content-Type` | `application/json` |
| `X-Open-Retrieve-Api-Key` | 与服务端 `open_retrieve.api_key` 或 `open_retrieve.api_keys[]` 中某项**完全一致**（含长度） |

### 4.2 JSON Body

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | **是** | 用户问题或检索语句 |
| `knowledge_base_ids` | string[] | 条件 | 库级范围；与 `knowledge_ids` **至少填其一** |
| `knowledge_ids` | string[] | 条件 | 知识 ID 级范围 |
| `match_count` | int | 否 | 期望返回的分片条数上限（服务端可再限制上限） |

### 4.3 成功响应（要点）

HTTP `200`：

```json
{
  "success": true,
  "data": [
    {
      "knowledge_base_id": "kb-001",
      "knowledge_id": "doc-1",
      "content": "分片文本",
      "score": 0.92,
      "match_type": "embedding"
    }
  ]
}
```

具体字段以线上返回为准。

### 4.4 调用示例

```bash
curl -sS -X POST "https://zsk.t.nxin.com/api/v1/open/knowledge/retrieve" \
  -H "Content-Type: application/json" \
  -H "X-Open-Retrieve-Api-Key: YOUR_OPEN_RETRIEVE_KEY" \
  -d "{\"query\":\"退款规则\",\"knowledge_base_ids\":[\"kb-001\"],\"match_count\":10}"
```

### 4.5 对接注意

- 若返回 `401` 且提示缺少认证：开放检索路径仅免除**用户 JWT**，仍必须携带有效的 `X-Open-Retrieve-Api-Key`。
- 路径末尾是否带 `/` 以网关与服务配置为准；若遇鉴权异常，可尝试与文档示例保持一致的 URL 形式。
