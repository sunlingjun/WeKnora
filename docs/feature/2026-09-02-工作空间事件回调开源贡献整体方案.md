## 1. 开源诉求（写进 Issue / PR 的理由）

自托管 WeKnora 需要把工作空间**自己拥有的**知识生命周期推给外部索引、归档或其它产品：

- 列表 API 只能轮询，且漏掉 worker 侧 `parse_completed`
- Embed 聊天 Webhook 是会话消息、只签 body、不重试，不能当知识变更总线
- 对接方不应为了拉源文件而持有长期空间 API Key

P0：归属空间的知识 / 知识库 / 成员出站回调 + HMAC + 短时下载票 + Owner 设置页 + website-docs + 本设计文档。

## 6. 不贡献清单（二开零携带）

移植纪律：从 `upstream/main` 长出的文件，只允许 webhook 相关 diff。fork 叠加层里「多出来的能力」整文件不进 PR。

### 6.1 认证与品牌（整文件 / 整段禁止）

| 路径或内容 | 原因 |
|------------|------|
| `internal/handler/cas_auth.go`、`auth_cas.go`、`tryNXINCASAuth` | 私有 SSO |
| `frontend/src/utils/casSession.ts`、`stores/cas.ts`、`views/auth/JoinCas.vue` | 同上 |

| 成员「按手机号导入」等私有组织通讯录 | 非上游成员模型 |

`frontend/src/utils/request.ts`、`Settings.vue`、四套 i18n：**只挑 webhook hunk**，禁止顺手带上上面任何一段。

### 6.2 私有知识/检索能力（禁止绑进本 PR）

| 路径或内容 | 原因 |

| `internal/handler/knowledge_catalog.go`、`knowledge_catalog*.go`、`types/knowledge_catalog.go` | fork 目录拉取，上游无此 API |

### 6.3 私有文档、密钥、示例语料

## 9. Issue 正文（可直接开）

标题：`feat: 工作空间知识生命周期出站回调`

```markdown
## 背景

本设计已与 WeKnora 维护者沟通，确定开发。

自托管 WeKnora 目前没有工作空间级的知识生命周期**出站** Webhook。对接方只能轮询列表 API，会漏掉 worker 侧的 `parse_completed`。嵌入渠道的聊天 Webhook 是另一套协议（会话消息、只签 body、不重试）。

## 方案

由 Owner 配置 HTTPS 回调（每空间最多 5 个）：

- outbox + 独立 asynq `webhook` 池（隔离方式对齐 Wiki）
- P0 事件：`knowledge.created|parse_completed|parse_failed|deleted|batch_deleted`、`kb.created|deleted`、`rbac.member_added|removed`、`webhook.test`
- HMAC-SHA256 签 `timestamp + "." + raw_body`
- 短时下载票：`GET /api/v1/files/knowledge-download/:id`（现网 `GET /knowledge/:id/download` 不改）
- 设置 → 空间 → 事件回调（仅 Owner）

设计文档随 PR 提交：`docs/workspace-webhooks.md`

一个功能 PR（后端 + 设置页 + 文档）。

## 本 PR 不做

- 组织共享扇出 / `kb.share_*`
- 改 `/knowledge/:id/download`
- 在载荷里放文件正文、JWT 或空间 API Key
- 与 Embed 或 IM 入站 webhook 合并

## 安全

SSRF、HTTPS、密钥不回显、票绑定 purpose、outbox 保证至少一次，接收方按包络 `id` 去重。
```
