## 0. 范围

**做：** 远端用 **空间绑定 `X-API-Key`**（`retrieve`）拉取当前工作空间有权限的知识库目录，以及指定库内知识的全量元数据。

权限并集：

- `owned`：本空间非临时知识库
- `org_share`：其它空间经组织 **`kb_shares`** 分享进来的库

**不做：**

| 项 | 原因 |
|----|------|
| 广场 `knowledge_base_members` / `/joined` | 人维度，不是空间授权 |
| Agent 分享可见的库 | 不在 `kb_shares` |
| query/path `tenant_id` | 空间只来自 Auth ctx |
| 文件二进制、`file_path`、下载票 | 下文件走现网 download |
| `open_retrieve` | 无空间 ACL |
| 无分页整库数组、嵌套 `{kbs:[{knowledge:[]}]}` | 无上界 |
| 软删行、change feed | 删除靠 webhook / 后续游标 |
| 改现网 `/knowledge-bases`、`/shared-knowledge-bases`、`/:id/knowledge` | Catalog 是新面 |

**和 Webhook 的分工**（`2026-08-31-工作空间知识事件回调设计.md` §0）：

| | Catalog（本文） | Webhook |
|--|----------------|---------|
| 作用 | 空间 Key 拉「自有 ∪ 组织分享」**全量底** | 归属空间的**增量**推送 |
| 组织分享库 | 列表 + 按库扫知识 | P0 **没有**事件 |
| 源文件 | `can_download=true` 时 `GET /knowledge/:id/download` | 5 分钟票 → `/files/knowledge-download/:id`（仅归属空间） |

成员空间对分享库：**只能靠 Catalog 建底**；`updated_after` 轮询看不到删除。

**主调用方：** `scope_type=tenant` 的 `X-API-Key`。JWT Viewer+ 可调同一路由，不是对接文档的主路径。

## 1. 方案 B 数据流

```text
  远端
    │  X-API-Key（空间 Key，retrieve）
    ▼
  GET /knowledge-catalog/knowledge-bases
    │  ListAuthorizedCatalogKBs(ctx)
    │    owned  ← ListKnowledgeBasesByTenantID(is_temporary=false)
    │    org_share ← ListSharedKnowledgeBases（现网 3-D cap，已 skip 自己分享出去）
    │    ∩ Key.knowledge_base_ids
    ▼
  本地建库目录（id, owner_tenant_id, can_download）
    │
    │  对每个 kb_id
    ▼
  GET /knowledge-catalog/knowledge?kb_id=&cursor=&limit=
    │  kb 必须在授权集合，否则 404
    │  ListPaged…(OwnerTenantID, kb_id)   ← 禁止用调用者 tenant 滤分享库
    ▼
  仅 can_download 且 type=file
    → GET /api/v1/knowledge/:id/download
```

P0 **按库扫**。`kb_id` 必填。跨库一次游标是 P1，本 PR 不做。

## 2. 已冻结

1. **空间** = Auth 注入的 tenant。空间 Key 用行上的 `tenant_id`；带错 `X-Tenant-ID` 由 Auth 403。Catalog **不读**该 Header。Platform Key 不写进对接主路径。
2. **分享** = `kb_shares`。`ListSharedKnowledgeBases` 为唯一分享数据源。
3. **授权单元** = `(owner_tenant_id, kb_id)`。知识行 `tenant_id` 永远是库属主。
4. **ACL 不抄** `SearchKnowledge`（那一层含广场 joined）。
5. **`permission`** = 3-D cap **之后**：`min(share, 组织内角色)` + `applyTenantRoleCap`。scoped API Key 的 ctx 角色是 Viewer，分享库几乎总是 `viewer`。
6. **`can_download`** 与 `KBAccessWrite` 对齐，挂在库上。分享 `viewer` 可列知识、不能下源文件。
7. **计数** = `CountKnowledgeByKnowledgeBaseID(owner_tenant, kb_id)`，不用 FAQ chunk 数。
8. 响应禁止 `file_path`、`vector_store_id`、票、正文。
9. 路由独立组 `/api/v1/knowledge-catalog`，`apiKeyRetrieve`；未登记 Key 默认拒绝。
10. 现网三个列表接口行为不变。

## 3. 授权集合

函数：`ListAuthorizedCatalogKBs(ctx) []CatalogKB`（5.1 / 5.2 共用）。

```text
CatalogKB:
  ID, Name, Type, Description, UpdatedAt
  AccessSource: owned | org_share
  OwnerTenantID
  Permission: viewer | editor | admin
  CanDownload: bool
  KnowledgeCount: int64
  OrganizationID, ShareID   // 仅 org_share
```

去重：同一 `kb_id` 只保留一条；撞车时标 `owned`。多组织分享同一库：保留 cap 后权限更高的那条 share（与现网 map 逻辑相同）。

**计入：**

| `access_source` | 来源 |
|-----------------|------|
| `owned` | `ListKnowledgeBasesByTenantID(当前 tenant)` 且 `!IsTemporary` |
| `org_share` | `ListSharedKnowledgeBases(当前 tenant, TenantRoleFromContext)` |

**永不计入：** 临时库、软删库、广场、Agent 分享、`SourceTenantID == 当前 tenant` 的 share 行。

Key 白名单非空：两层都 `AllowsKnowledgeBase`。要同步分享库，须把那些 id 写入 Key，或用空白名单。

`CanDownload`：

| 条件 | 值 |
|------|----|
| `owned` + API Key | `true`（own = Admin，角色门对 Key short-circuit） |
| `owned` + JWT 且 ≥ Contributor | `true` |
| `owned` + JWT Viewer | `false` |
| `org_share` 且 cap 后 ≥ editor | `true` |
| `org_share` 且 cap 后 = viewer | `false` |

硬顶 2000 库；超过则 `truncated=true`，多出的不返回（P1 再做库级游标）。

## 4. 接口契约

组：`/api/v1/knowledge-catalog`  
Auth 之后；JWT `Viewer()`；API Key `retrieve` 或 full-access。  
成功体：`{"success":true,"data":{...}}`。失败走现网 `AppError`。

### 4.1 `GET /api/v1/knowledge-catalog/knowledge-bases`

| Query | 默认 | 说明 |
|-------|------|------|
| `include_org_shared` | `true` | `false` 时只返回 `owned` |
| `type` | 空=全部 | `document` / `faq` / `wiki` |

```json
{
  "success": true,
  "data": {
    "tenant_id": 42,
    "generated_at": "2026-09-01T01:00:00Z",
    "knowledge_bases": [
      {
        "id": "kb-own-1",
        "name": "产品文档",
        "type": "document",
        "description": "",
        "access_source": "owned",
        "owner_tenant_id": 42,
        "permission": "admin",
        "can_download": true,
        "knowledge_count": 120,
        "updated_at": "2026-08-30T08:00:00Z"
      },
      {
        "id": "kb-share-9",
        "name": "集团制度",
        "type": "document",
        "description": "",
        "access_source": "org_share",
        "owner_tenant_id": 7,
        "organization_id": "org-1",
        "share_id": "share-1",
        "permission": "viewer",
        "can_download": false,

```

| 字段 | 约定 |
|------|------|
| `tenant_id` | **调用者空间**（Key 所属） |
| `owner_tenant_id` | 库归属；`org_share` 时 ≠ `tenant_id` |
| `permission` | `owned` 固定 `admin`；`org_share` 为 cap 后角色 |
| `knowledge_count` | 属主空间知识行数 |

Wiki 库可以出现在本列表。

### 4.2 `GET /api/v1/knowledge-catalog/knowledge`

P0 **`kb_id` 必填**。

| Query | 默认 | 说明 |
|-------|------|------|
| `kb_id` | **必填** | 不在授权集合 → 404 |
| `limit` | 100 | 1～500 |
| `cursor` | 空=从头 | 上一页 `next_cursor` |
| `updated_after` | 空 | RFC3339，`updated_at >`；看不到删除 |
| `parse_status` | 空=全部 | 与现网列表同一枚举 |

实现：`kb` 在授权集合中取出 `OwnerTenantID`，调用  
`ListPagedKnowledgeByKnowledgeBaseID(ownerTenantID, kb_id, page, filter)`。  
**禁止** `MustTenantIDFromContext()` 当分享库 WHERE。  
**禁止** 无分页 `ListKnowledgeByKnowledgeBaseID`。

排序：`(updated_at ASC, id ASC)`。`cursor` 不透明（建议 `base64url` 编码 `updated_at,id`）。

缺 `kb_id` → 400。Wiki 库无 `knowledges` 行 → `items=[]`，`has_more=false`。

```json
{
  "success": true,
  "data": {
    "tenant_id": 42,
    "kb_id": "kb-share-9",
    "items": [
      {
        "id": "4c4e7c1a-09cf-485b-a7b5-24b8cdc5acf5",
        "knowledge_base_id": "kb-share-9",
        "knowledge_type": "file",
        "title": "报销制度.pdf",
        "file_name": "报销制度.pdf",
        "file_type": "pdf",
        "file_size": 102400,
        "folder_path": "制度/财务",
        "parse_status": "completed",
        "enable_status": "enabled",
        "source": "web",
        "has_file": true,
        "created_at": "2026-08-01T00:00:00Z",
        "updated_at": "2026-08-20T00:00:00Z"
      }
    ],
    "next_cursor": "eyJ1IjoiLi4uIiwiaSI6Ii4uLiJ9",
    "has_more": true
  }
}
```

| 字段 | 约定 |
|------|------|
| `knowledge_type` | REST `type`：`file` / `url` / `manual` / `faq` |
| `has_file` | `file` 且源文件仍在；不暴露路径 |
| `folder_path` | 空串=库根 |
| `next_cursor` | `has_more=false` 时 `""` |

取消分享后下一页 404 或不再出现该库文档：以**当前请求**的授权集合为准。

含：所有未删除行（含解析中/失败/禁用）。不含软删、不含手工正文。

### 4.3 远端顺序（对接写进手册的唯一顺序）

完整 curl / 脚本 / 自测见 `docs/api/2026-09-01-工作空间授权知识目录拉取.md`。

```text
1. GET /api/v1/knowledge-catalog/knowledge-bases
2. 对 data.knowledge_bases[].id：
     循环 GET /api/v1/knowledge-catalog/knowledge?kb_id=&limit=100&cursor=
     直到 has_more=false
3. 仅当该库 can_download=true 且 knowledge_type=file：
     GET /api/v1/knowledge/{id}/download
```

不要对 `can_download=false` 的库撞 download（组织分享 viewer / JWT Viewer 会 403）。
响应 JSON **不得**出现 `file_path`、`vector_store_id`。源文件只走第 3 步的二进制流。

## 5. 错误

| 情况 | HTTP | 说明 |
|------|------|------|
| 未认证 | 401 | Auth |
| Key 无 `retrieve` / 未登记路由 | 403 | APIKeyGate |
| 缺 `kb_id`、非法 `limit`、非法 `updated_after` | 400 | `NewBadRequestError` |
| `kb_id` 不在授权集合 | 404 | `NewNotFoundError`（不泄露跨空间存在） |
| 内部 | 500 | 不返回存储路径 |

空目录是 200 + `knowledge_bases=[]`，不是 404。

## 6. 实现接线

```text
internal/types/knowledge_catalog.go          # CatalogKB / 响应 DTO
internal/application/service/knowledge_catalog.go
internal/handler/knowledge_catalog.go
internal/router/routes_knowledge.go          # RegisterKnowledgeCatalogRoutes
internal/handler/knowledge_catalog_test.go
```

`RegisterKnowledgeCatalogRoutes` 在 `router.go` 里紧挨 `RegisterKnowledgeBaseRoutes` 之后。独立 `v1.Group("/knowledge-catalog")` + `apiKeyRetrieve(apiKeyFullAccess())` + `g.Viewer()`。

Service 依赖：`KnowledgeBaseService`（或 repo）、`KBShareService.ListSharedKnowledgeBases`、`KnowledgeService.ListPagedKnowledgeByKnowledgeBaseID` / `CountKnowledgeByKnowledgeBaseID`。3-D cap **不要重写**，调现网分享列表。

Handler 薄：组 ctx → Service → JSON。分享库计数用 `OwnerTenantID`。

## 7. 验收（单测必须钉）

- [ ] 空间 Key：2 owned + 1 org_share → 3 条；`access_source`、`owner_tenant_id` 正确；临时库不出现。
- [ ] 自己分享出去的库只在 `owned`，不重复 `org_share`。
- [ ] `include_org_shared=false` 只有 owned。
- [ ] 取消分享后再 GET 库列表，该库消失；再 `?kb_id=` 该库 → 404。
- [ ] `?kb_id=` 分享库：返回属主空间下的知识，**不是空数组**（回归「错用调用者 tenant」）。
- [ ] 无权 / 白名单外 `kb_id` → 404。
- [ ] 白名单只含库 A：分享库 B 与其它自有库都不在 4.1。
- [ ] scoped retrieve Key + 分享 viewer：`permission=viewer`，`can_download=false`。
- [ ] 自有库 + 同一 Key：`can_download=true`。
- [ ] 缺 `kb_id` → 400；`limit=0` 或 `>500` → 400。
- [ ] 游标第二页稳定（`updated_at,id`），无重复 id。
- [ ] 响应 JSON 无 `file_path`、无 `vector_store_id`。
- [ ] 未登记能力的 Key → 403。
- [ ] 现网 `GET /knowledge-bases`、`/shared-knowledge-bases`、`/knowledge-bases/:id/knowledge` 行为不变。

## 附录 B — 2026-09-01 复测（已吸收进正文）
