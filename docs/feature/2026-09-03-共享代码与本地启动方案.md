# 2026-09-03 共享代码与本地启动方案

> **仓库**：`WeKnora-slj`（本仓为源仓，管理开源分支并对接上游；自有能力在本仓开发分支完成）  
> **对照仓**：`NXIN-WEKNORA`（部署/环境仓；业务缺陷回灌 slj，禁止在 NXIN 回灌业务代码）  
> **目的**：固定两套互不污染的启动路径——**自有/共享开发** vs **开源贡献联调**，避免再混用 PG / 环境变量。

---

## 0. 一页纸

| 场景 | 分支 | 数据库 | 启动方式 |
|------|------|--------|----------|
| **自有 / 共享开发**（CAS、农信定制、合入前联调） | `upgrade/v0.7.1-to-v0.7.2` → 测通后合 `stable/2026-08-14-nxin-v0.7.2` → 再推进 `NXIN-WEKNORA` `dev` | `WeKnora-postgres-dev` **:5432** / `WeKnora` | 基建 + `run-local-*.py`（**HTTPS :8080**）+ `frontend npm run dev`（**HTTPS :443**，访问 `https://zsk.t.nxin.com/`） |
| **开源贡献联调**（对上游 PR，零农信） | `contrib/*`（如 `contrib/workspace-webhooks`） | `weknora-oss-postgres` **:15432** / `weknora` | `docker/2026-09-02-oss-contrib-postgres.yml` + 临时改 `.env` 或进程环境指向 15432 |

**硬规则**

1. 同一时间只开一套 PG：自有用 5432，开源用 15432；切场景前先停另一套。  
2. 自有开发**禁止**手写 `DB_*=weknora/15432` 起服务；必须用下方本地脚本加载 `.env`（避免 Cursor/终端残留环境变量盖掉 `.env`）。  
3. 开源分支代码逻辑与自有分支隔离；开源语义可回写自有，但合入路径仍走 upgrade → stable → NXIN。

## 2. 自有 / 共享开发：本地启动方案（默认）

### 2.1 前置

- 已配置仓库根目录 `.env`（gitignore，勿提交）。自有开发关键项示例：

| 变量 | 典型值 |
|------|--------|
| `DB_HOST` / `DB_PORT` | `localhost` / `5432` |
| `DB_USER` / `DB_PASSWORD` / `DB_NAME` | `postgres` / `postgres123!@#` / `WeKnora` |
| `REDIS_ADDR` / `REDIS_DB` | `127.0.0.1:6379` / `0` |
| `DOCREADER_ADDR` | `localhost:50051` |
| `MINIO_ENDPOINT` | `localhost:9000`（`STORAGE_TYPE=minio` 时） |
| `APP_PORT` / `GIN_MODE` | `8080` / `debug` |
| `FRONTEND_PORT` | `80`（Vite HTTPS） |
| `SSL_CERT_PATH` / `SSL_KEY_PATH` | `./ssl/cert.pem` / `./ssl/key.pem` |

- Docker Desktop 可用。  
- **HTTPS（自有本地必开）**  
  - 后端：`config/config.yaml` → `server.https.enabled: true`，证书 `ssl/cert.pem` + `ssl/key.pem`（进程内 TLS → **https://127.0.0.1:8080**）。  
  - 前端：Vite **HTTPS 监听 443**（浏览器访问 `https://zsk.t.nxin.com/` 默认走 443，不是 80）。  
  - `hosts`：`127.0.0.1 zsk.t.nxin.com`  
  - 证书 SAN 须含 `zsk.t.nxin.com`（仓库 `ssl/`；可用 `scripts/generate-ssl-cert.ps1` 或 openssl 重签）。  
  - `.env` 里 `FRONTEND_PORT=80` 是 **Docker 映射习惯**；本地 Vite HTTPS 以 `vite.config.ts` 的 **443** 为准。  
  - Windows 绑 443 通常需**管理员**终端。

### 2.2 基建（只起依赖，不起 app/frontend 容器）

```bash
# 仓库根目录
docker compose -f docker-compose.dev.yml up -d postgres redis

# 常用：文档解析 + 对象存储（按 .env 的 profile / 已有容器名亦可 docker start）
docker start WeKnora-postgres-dev WeKnora-redis-dev WeKnora-docreader-dev WeKnora-minio-dev
```

容器约定（`docker-compose.dev.yml`）：

| 容器名 | 端口 | 用途 |
|--------|------|------|
| `WeKnora-postgres-dev` | `5432` | 自有业务库 |
| `WeKnora-redis-dev` | `6379` | Redis / asynq |
| `WeKnora-docreader-dev` | `50051` | 文档解析 |
| `WeKnora-minio-dev` | `9000` / `9001` | 对象存储 |

确认健康：

```bash
docker ps --filter "name=WeKnora-postgres-dev"
docker exec WeKnora-postgres-dev pg_isready -U postgres -d WeKnora
```

### 2.3 后端（必用脚本，勿裸跑 exe 且不带 .env）

Windows / 跨平台推荐：

```bash
# 加载 .env 后 go run ./cmd/server（覆盖会话里残留的 DB_*）
python scripts/2026-09-01-run-local-app.py
```

或（强制把依赖指到本机映射端口，适合 compose.dev）：

```bash
python scripts/2026-09-01-run-local-server.py
```

脚本行为：

1. 读取根目录 `.env` 写入当前进程环境（去掉引号）。  
2. `run-local-server.py` 额外强制 `DB_HOST=localhost`、`REDIS_ADDR=localhost:6379`、`DOCREADER_ADDR=localhost:50051`、`MINIO_ENDPOINT=localhost:9000` 等。  
3. 保证 `LOCAL_STORAGE_BASE_DIR` 落在仓库 `.local-data/files`。  
4. 执行 `go run ./cmd/server`。

成功标志：日志出现 `Server is running at https://0.0.0.0:8080`（进程内 TLS），且启动 env 打印为 `DB_PORT=5432` / `DB_NAME=WeKnora`。

**不要**：在 Cursor 终端残留 `DB_PORT=15432` 时直接 `.\server-upgrade.exe`——进程环境会盖掉 `.env`，连到已停的开源库。

### 2.4 前端（HTTPS :443）

```bash
# 建议「以管理员身份」开终端（绑定 443）
cd frontend
npm run dev
```

| 项 | 值 |
|----|-----|
| 访问 | **https://zsk.t.nxin.com/**（hosts → 127.0.0.1） |
| 端口 | **443**（HTTPS 默认端口；勿依赖 :80） |
| TLS | `ssl/cert.pem`（SAN 含 `zsk.t.nxin.com`） |
| API 代理 | `/api`、`/files` → `https://127.0.0.1:8080`（`secure: false`） |

自测：`curl.exe -k -I https://zsk.t.nxin.com/` 应返回 200。若只开了 :80，无端口的 https URL 会连不上。

### 2.5 登录行为（自有分支约定，便于复测）

| 操作 | 期望 |
|------|------|
| 未登录访问业务页（非 `/login`） | 跳 CAS（本机一般为 `cas.t.nxin.com`） |
| 直接打开 `/login`，CAS 已登录 | 进主页 / onboarding |
| 直接打开 `/login`，CAS 未登录 | 显示自有登录页（可密码登录或点「使用农信账号登录」） |

### 2.6 合入顺序（功能测通后）

```
upgrade/v0.7.1-to-v0.7.2
        │ 本地复测通过
        ▼
stable/2026-08-14-nxin-v0.7.2
        │ 再推进
        ▼
NXIN-WEKNORA dev（及后续 MR）
```

## 3. 开源贡献：共享上游联调启动方案

### 3.1 何时用

- 在 `contrib/*` 分支验证即将推上游的能力（例如 workspace webhook）。  
- 数据与农信库隔离，避免污染 `WeKnora` 本库。

### 3.2 开源专用 PG

```bash
docker compose -f docker/2026-09-02-oss-contrib-postgres.yml up -d
# 容器 weknora-oss-postgres → 127.0.0.1:15432
```

| 项 | 值 |
|----|-----|
| Host/Port | `127.0.0.1:15432` |
| User / Password / DB | `weknora` / `weknora_oss_local` / `weknora` |

Redis / docreader / minio 可继续复用 `WeKnora-*-dev`，但 **`REDIS_DB` 建议与自有错开**（例如开源用 `2`，自有用 `0`），避免 asynq 队列串扰。

### 3.3 启动注意

1. **先停**自有后端占用的 `:8080`。  
2. 临时将进程 DB 指到 15432（改会话环境或临时 `.env`，切回自有前务必还原）。  
3. 前端仍可 `npm run dev`，但当前工作区须在对应 `contrib/*` 检出。  
4. 联调结束后：

```bash
docker compose -f docker/2026-09-02-oss-contrib-postgres.yml stop
# 还原 .env / 清掉 DB_PORT=15432 等会话变量
# 再按第 2 节起自有环境
```

### 3.4 与自有分支关系

- 开源语义（如「仅配置才推送」webhook 门控）可移植进 `upgrade/*`，在自有环境复测。  
- **不要**在 `contrib/*` 提交农信 CAS / 品牌等定制。

## 5. 故障速查

| 现象 | 原因 | 处理 |
|------|------|------|
| `dial tcp 127.0.0.1:15432: connection refused` | 仍连开源库但容器已停，或会话 `DB_PORT=15432` 盖掉 `.env` | 用 `run-local-*.py`；`Remove-Item Env:DB_*` |
| 启动日志 `DB_NAME=weknora` 但人在自有分支 | 环境串台 | 核对脚本打印的 DB；停 15432 容器 |
| Redis `i/o timeout` / asynq 报错 | Redis 忙或 DB 串队列 | 确认 `WeKnora-redis-dev`；自有 `REDIS_DB=0` |
| 访问 `/` 直接 CAS，找不到登录页 | 符合自有约定；要密码页请直开 `/login` | 见 §2.5 |
| 前端改了路由无效果 | Vite 未热更或仍在旧分支产物 | 硬刷新或重启 `npm run dev` |
