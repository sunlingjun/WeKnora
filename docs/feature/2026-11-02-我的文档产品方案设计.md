## 1. 背景与问题

### 1.1 诉求

依托农信知识库二开，建设服务 AI 的「我的文档」：

- Agent 产出需要有默认落点，并能被后续任务继续读写（对齐 WorkBuddy「接住产物 → 接着干」）。
- 个人资产与企业知识库解耦：个人文件**不必**进入知识库，也**不必**付向量化成本。
- 知识分享尽量**只保存一份**，分享/挂库维护关系；取消关系不等于删文件。
- 支持 AI 生成写入；问答历史可导出并经换票开放只读访问。
- 用户在熟悉的 home 工作台内完成管理，而不是另起孤立站点。

### 1.2 竞品要点（吸收什么）

| 产品 | 可吸收 |
|------|--------|
| **WorkBuddy 资料库** | 「我的文档」vs 团队空间；会话产物默认落入个人；任务内 read/write；MD/HTML/CSV 等 AI 原生格式；挂外部知识库作连接器而非混为一谈 |
| **ChatGPT Library / Projects** | 上传与生成文件统一入库；可再次加入对话；项目级上下文（对应我们的目录/任务夹） |
| **元宝 × 腾讯文档** | 对话产物一键沉淀；外链/在线文档互通（对应换票与导出） |
| **农信知识库现网** | 分享关系模型、下载票 / renew、CAS + `X-Tenant-ID`、挂载后走既有解析流水线 |

### 1.3 与现有「个人 private KB」的关系

天工方案中「个人知识」= 企业 tenant 内 `visibility=private` 的 KB，**面向检索**。

「我的文档」更底层：

- 先有个人文件资产；
- **需要检索时**再挂到某企业某 KB，生成派生 Knowledge；
- 未挂载时不占用该 KB 的解析/向量配额。

二者可并存：private KB 继续服务「个人知识问答」场景；MyDoc 服务「个人文件 + 全 Agent 读写中枢」。

## 2. 产品定位

### 2.1 一句话

**「我的文档」是农信 AI 场景下的账号级个人资产中枢：人与任意 Agent 共同沉淀、整理、分享文件；默认是文件与关系，不是知识库。**

### 2.2 是 / 不是

**是**

- 用户全局一份资产树（切企业不换另一套个人文件）
- 多类型文件：办公文档、AI 三件套、多媒体、压缩包等（见 §4）
- Agent 经 HTTP/MCP 直接 list/read/write
- 分享 = 查看 + 下载（关系）；问答历史等可换票
- 可选挂企业知识库 → 才解析/分片/向量
- 所有者在线编辑 MD/文本；完整目录管理
- home 工作台一级入口，功能闭环

**不是**

- 不是企业知识库 / 共享知识广场本身
- 不是默认 RAG 语料库
- 不做多人协同编辑
- 首期不做对象存储物理删除、完整回收站
- 首期不做组织内公开广场、网页剪藏、文件夹级分享扇出

### 2.3 用户价值

| 角色 | 价值 |
|------|------|
| 终端用户 | 个人与 AI 产物一处沉淀；可整理、分享、按需挂进知识库问答 |
| Agent / 业务方 | 统一写入契约，不绑死某一 Agent 产品 |
| 企业管理员 | 员工个人原文默认不可窥；仅挂入本企业 KB 的派生内容受企业权限治理 |
| 平台 | 向量与解析成本可控；一份原文多关系复用 |

## 3. 架构总览

```text
┌─────────────────────────────────────────────────────────────┐
│ nxin-home Brain 工作台                                        │
│  … | 知识中心 | 【我的文档】 | 智能体广场 | …                   │
│                    │                                          │
│                    │ 完整 MyDoc UI（原生，调 API；非 iframe）   │
└────────────────────┼──────────────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────────────┐
│ WeKnora-slj（实现主战场，v0.8.3）→ 再合入 NXIN-WEKNORA         │
│  Knowledge 域（企业 KB / 解析 / 向量 / 问答）                   │
│  MyDoc 域（新增）：Node/File/Share/Ticket/Mount + ACL          │
│  HTTP /api/v1/my-docs/*  +  MCP mydoc_*  （同一权限内核）       │
│  DDL：migrations/versioned/feature/0000018_mydoc.*（手工）     │
└─────────────────────────────────────────────────────────────┘
          │
          ├─ 对象存储：原文只存一份
          ├─ 挂载(P1) → 派生 Knowledge（落目标 tenant/KB）
          └─ 任意 Agent（天工/学联网/知识库问答/第三方）用户委托写入
```

**原则**

1. 物理文件一份；分享 / 挂库 / 票 = 关系或派生。  
2. 取消分享、卸挂、归档 ≠ 物理删原文。  
3. Agent 权限永远 ≤ 当前委托用户。  
4. `X-Tenant-ID` 用于挂库目标与审计，不用于切换「另一套我的文档」。

## 4. 文件类型与内容形态

### 4.1 业务 kind（逻辑类型）

| kind | 说明 | 来源 |
|------|------|------|
| `upload` | 用户本地上传 | Web / Agent 代传 |
| `ai_artifact` | AI 生成产物 | **任意** Agent 写入 |
| `qa_snapshot` | 问答历史快照 | 会话导出 |
| （节点）`folder` | 目录 | 用户 / Agent 建夹 |

### 4.2 存储与预览：多文件类型（首期需支持）

对齐 WorkBuddy「多种格式进同一棵树」，首期至少：

| 分类 | 扩展名（示例） | 预览策略（P0） | 所有者在线编辑 |
|------|----------------|----------------|----------------|
| AI 三件套 | `md` / `markdown`、`csv`、`html`/`htm` | 内置预览（MD 渲染 / 表预览 / HTML 沙箱） | **MD/纯文本可编辑**；HTML/CSV P0 可先只预览+下载，P1 再增强编辑 |
| 办公文档 | `pdf`、`doc`/`docx`、`ppt`/`pptx`、`xls`/`xlsx` | PDF 内嵌预览；Office 优先下载或只读预览组件（按现网能力） | 否（下载后本地改再回传为新版本可 P1） |
| 纯文本 | `txt`、`json`、`yaml`、`xml` 等 | 文本预览 | 是（文本类） |
| 图片 | `png`/`jpg`/`jpeg`/`gif`/`webp` | 图片预览 | 否 |
| 音视频 | `mp3`/`wav`/`mp4`/`mov` 等 | 媒体播放器或下载 | 否 |
| 压缩包 | `zip` | 不预览，提供下载 | 否 |

**约束**

- MIME + 扩展名双校验；单文件大小 / 总量配额可配置（P1 细化数值）。  
- 未知类型：允许上传为「附件」，仅下载，不强制预览。  
- **挂库时**再走 DocReader 解析白名单；未挂库不触发解析。  
- 病毒扫描 / 内容安全若有现网能力则复用（实现阶段对齐）。

## 5. 对象模型

### 5.1 实体

**MyDocNode**（树节点）

- `id`, `owner_user_id`（CAS 用户全局 ID，与 `users` 表主键类型对齐实现时再钉死），`parent_id`, `name`, `type`=`folder|file`
- `archived`（bool）, `archived_at`
- `path`：**P0 可不落库**，由服务按父链拼装面包屑；若列表性能不够再加物化列（另迁 feature DDL）
- `created_at` / `updated_at`
- **同级唯一（实现约束）**：同一 `owner_user_id + parent_id + name` 且未归档下不可重复（DDL 可加部分唯一索引，或服务层强校验；当前 `0000018` 未建唯一索引，**P0 必须服务层校验**）

**MyDocFile**（file 载荷）

- `node_id`, `kind`=`upload|ai_artifact|qa_snapshot`
- `storage_key`, `mime`, `size`, `content_hash`, `version`
- `source_agent`, `source_session`（可空）
- `extra`（JSON：如 qa 的 `session_id`、页数等）

**MyDocShare**

- `doc_id`（file node）, `grantee_user_id`, `role`=`viewer` only
- 取消分享 = 删/废关系行
- 注意：DDL 对 `doc_id` 为 `ON DELETE CASCADE`，但产品禁止物理删节点；归档**不**触发 CASCADE。若将来物理删，需先清分享/票/挂载

**MyDocTicket**

- `doc_id`, `purpose`=`preview|download`, `token_hash`（只存哈希，明文票仅签发时返回一次）, `expires_at`, `revoked`, `created_by`
- 短 TTL + `renew`；对齐现网 knowledge-download 票思路（可无状态签名票 + 可选落库 revoke 名单；二选一实现，P0 推荐**签名票为主、库表作 revoke/审计**）

**MyDocMount**（P1 使用，P0 仅建表占位）

- `doc_id`, `tenant_id`, `knowledge_base_id`, `derived_knowledge_id`
- `index_status`=`pending|ready|stale|failed`
- 允许同一 `doc_id` 多行（跨企业多挂）
- 卸挂：删关系 + 清理派生 Knowledge/分片/向量；**保留** MyDoc 原文

### 5.2 关系示意

```text
User ──owns──► MyDocNode (folder|file)
                 ├─ MyDocShare ──► users (viewer: 预览/下载)
                 ├─ MyDocTicket ──► 临时只读访问
                 └─ MyDocMount ──► Tenant/KB ──► derived Knowledge (+chunks/vectors)
```

### 5.3 关键规则

1. 分享 / 挂库 / 票 **不复制** 对象存储对象。  
2. 所有者更新文本内容 → `version++`；相关 mount 标 `stale`，可异步重解析。  
3. 归档文件夹 = 子树一并 `archived=true`，默认树不可见；管理端可查。  
4. 归档后：分享访问返回「已归档」；已挂载可提示 stale / 暂停检索（实现时二选一，推荐：**归档即对派生检索不可用，卸挂或保留挂载但 enable=false**）。  
5. Agent 只能写 `owner_user_id = 当前委托用户` 的树。  
6. 移动：改 `parent_id`，环检测；不改变 `doc_id`、不自动改挂库目标。

## 6. 权限与访问

### 6.1 矩阵（首期）

| 动作 | 所有者 | 被分享 viewer | 持票者 | Agent（代用户） |
|------|--------|---------------|--------|-----------------|
| 列表/预览 | ✓ | ✓（与我共享） | ✓（票面允许） | ✓ ≤ 用户 |
| 下载 | ✓ | ✓ | ✓ | ✓ ≤ 用户 |
| 改 MD/文本、覆盖写 | ✓ | ✗ | ✗ | 仅代所有者 |
| 目录：建/改名/移动/归档 | ✓ | ✗ | ✗ | 仅代所有者 |
| 分享/收回 | ✓ | ✗ | ✗ | 默认关闭或需显式工具 |
| 挂库/卸挂 | ✓（且对目标 KB 有权限） | ✗ | ✗ | 需显式工具 |
| 物理删除 | 首期全员 ✗ | | | |

### 6.2 身份与跨企业

- 归属键：`owner_user_id`（CAS 全局用户）。  
- 请求可带 `X-Tenant-ID`：挂库目标、审计、企业侧入口上下文。  
- 「我的文档」列表**不**因切企业而切换资产集。  
- 企业管理员**默认不能**浏览员工 MyDoc 原文（除非被分享或持票）。  
- 挂库：校验用户对目标 tenant + KB 的相应权限；派生索引落在目标企业。

### 6.3 换票

- 所有者（或授权 Agent）签发短票；`renew` 有 grace。  
- **收回分享时**：同步作废该文档未过期票（默认策略）。  
- 问答历史快照的主外发路径。

## 7. Agent / API 契约

### 7.1 鉴权

- HTTP：CAS Cookie / JWT；挂库时需要有效企业上下文。  
- MCP：用户委托会话；工具参数带 `source_agent`。  
- **禁止**用企业空间 API Key 写入他人 MyDoc；空间 Key 最多消费「已挂入本空间」的派生 Knowledge。

### 7.2 HTTP（前缀建议 `/api/v1/my-docs`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/tree` | 目录树；`view=owned\|shared`；默认排除 `archived` |
| POST | `/folders` | 建目录 |
| PATCH | `/nodes/:id` | 重命名 |
| POST | `/nodes/:id/move` | 移动 `{ parent_id }` |
| POST | `/nodes/batch-move` | 批量移动 |
| POST | `/nodes/:id/archive` | 归档隐藏（文件夹含子树） |
| POST | `/files` | 上传 / AI 写入（multipart 或 JSON content） |
| GET | `/files/:id` | 元数据 |
| GET | `/files/:id/content` | 预览/下载 |
| PUT | `/files/:id/content` | 所有者改文本（升 version） |
| POST | `/files/:id/shares` | 分享 viewer |
| DELETE | `/shares/:id` | 取消分享 |
| POST | `/files/:id/tickets` | 发票 |
| POST | `/tickets/:id/renew` | 换票 |
| POST | `/files/:id/mounts` | 挂库（触发派生解析） |
| DELETE | `/mounts/:id` | 卸挂 |
| POST | `/qa-snapshots` | 从 session 导出快照 |

### 7.3 MCP tools（与上表同权）

`mydoc_list` / `mydoc_mkdir` / `mydoc_rename` / `mydoc_move` / `mydoc_archive` / `mydoc_read` / `mydoc_write` / `mydoc_share`（可开关）/ `mydoc_issue_ticket` / `mydoc_mount_kb`

### 7.4 AI 写入约定

- `kind=ai_artifact`，**任意 Agent** 可调用。  
- 可指定 `parent_folder_id`、文件名、MIME。  
- 冲突：`overwrite`（默认升 version）或 `new_name`；否则 409。  
- 成功返回 `doc_id`、路径；**不**自动挂库。

### 7.5 问答历史快照

- 输入 `session_id`（+ 消息范围）→ 生成 MD/JSON 入 MyDoc。  
- 可立刻发票给第三方只读。  
- 不自动向量化。

`AI工作台` | `技能广场` | `知识中心` | **`我的文档`** | `智能体广场` | …

### 8.2 「完整实现」范围（P0 必须在 home 内闭环）

home「我的文档」页内须覆盖本方案 P0 能力，而不是仅外链到知识库：

| 模块 | 能力 |
|------|------|

| 预览器 | 按 §4.2 多类型预览；文本/MD 所有者编辑保存 |
| 分享 | 选人分享 viewer；取消分享；复制下载/预览票链接（问答快照场景突出） |
| Agent 产物 | 展示 `source_agent`；支持从会话「存到我的文档」（若工作台会话侧有入口可互通） |

### 8.4 与知识中心 iframe 的关系

- 知识中心：继续嵌入 WeKnora 前端知识库能力（现 `KnowledgeCenter`）。  
- 我的文档：**优先 home 原生实现**（调用 WeKnora MyDoc API），以保证目录操作、分享、多类型预览与 Brain 视觉一致。  
- 若阶段性复用 WeKnora 前端路由，也必须在工作台以独立 tab 呈现，且功能清单与本方案 P0 对齐，不能只做半截列表页。

## 9. 挂库与派生索引（双通道）

1. 用户或 Agent 调用 mount，指定 `tenant_id + knowledge_base_id`。  
2. 服务端创建派生 `Knowledge`，走现有 DocReader → chunk → embed。  
3. 检索/问答只命中派生对象；权限走目标 KB 成员模型。  
4. 卸挂：删除派生数据与 mount 行；MyDoc 原文保留。  
5. 原文更新：mount → `stale` → 重解析任务。  
6. 跨企业多挂：各企业各有派生副本索引；配额按目标企业计。

## 11. 成功标准

1. home 顶栏在知识中心旁可见「我的文档」，且 P0 功能可在页内闭环完成。  
2. 任意对接 Agent 能将多类型产物写入用户 MyDoc，并在 home 中可见、可预览/下载。  
3. 未挂库文档**不**产生分片/向量；挂库后可检索；卸挂后检索不可用且原文仍在。  
4. 分享同事仅能看/下；取消分享后立即不可访问；换票过期或撤销后失效。  
5. 目录重命名/移动/归档行为符合预期；归档后默认树不可见。  
6. 企业管理员不能默认翻阅员工 MyDoc 原文。

## 12. 风险与开放点（实现前可再拍）

| 项 | 说明 | 建议默认 |
|----|------|----------|
| 全局中枢 vs 企业合规 | 跨企可见个人资产增加合规讨论 | 原文仅用户可见；企业只治理「挂入本企」的派生 |
| 归档后挂载 | 检索是否保留 | 归档 → 派生停用 |
| Office 在线预览 | 组件与许可证 | P0 可下载为主，PDF 优先预览 |
| 与天工 private KB 双轨 | 用户是否困惑 | 文案区分「个人文件」vs「个人知识库」；后续可做「一键挂到个人库」 |
| 配额数值 | 容量/单文件上限 | 实现计划单独立项 |
| 选人分享 | home/CAS 侧「按人」组件与 `grantee_user_id` 映射 | P0 先支持已知用户 ID/工号检索，对齐现网成员选择器若有则复用 |
| `owner_user_id` 与 users 主键 | CAS uid / UUID 混用风险 | 与 `middleware` 注入的 UserID 字符串**完全一致**，禁止再映射一层 |
| 跨 Agent 委托凭证 | MCP/HTTP 如何证明「代该用户」 | 复用现有用户会话；禁止空间 API Key 写 MyDoc（已拍板） |
| feature DDL 运维 | 测试/生产忘记手工执行 | 发布清单强制项；应用启动可选「缺表则明确报错」 |
