## 1. 「合并版」定义（完成标准）

同时满足以下条件，才视为本地合并版冻结、可开始贡献拆分：

| # | 标准 | 说明 |
|---|------|------|
| M1 | Tag 阶梯合并已在历史中 | `merge: … v0.4.0 / v0.5.2 / v0.6.3` 已存在（当前已满足） |
| M2 | 工作区干净或已有明确提交 | 当前大量前端/handler WIP 需收口提交（**不含** `server.exe` 等二进制） |
| M3 | 后端可编译 | `go build -o server.exe ./cmd/server` |
| M4 | 前端可构建 | `npm run type-check` + `npm run build`（或团队约定等价命令） |
| M5 | P0 保护项可勾选 | CAS / 共享 KB / open_retrieve / SvgIcon / Redis 双模式（见升级清单 §三） |
| M6 | Redis 与上游 TLS 对齐（本地） | 集群路径补 `common.RedisTLSConfig()`，避免本地生产开 TLS 时踩坑（贡献时也会用到） |
| M7 | （可选）打本地 Tag | 例如 `nxin-v0.6.3-merge.1`，作为贡献拆分与回滚基准 |

**本阶段不做**：把本地再 merge 进 `upstream/main` 当前 tip（已超前 Tag `v0.6.3` 很多 commit）。贡献仍从干净 `upstream/main` 另开分支移植。

## 3. 收口任务（按序）

### Task L1：整理 WIP 并提交（需确认后 commit）

**范围**：功能相关源码 + 必要文档；排除 `server.exe`、`server-test.exe`、`*.exe~`。

建议按语义拆 1～N 个 commit（示例）：

1. `fix(kb): …` — `knowledgebase.go`、列表/权限/共享广场  
2. `feat(frontend): …` — 上传确认、组织、Agent 流式 UI 等  
3. `docs: …` — `2026-07-14` API 手册、`2026-07-15` 贡献/收口方案  

**验收**：`git status` 仅剩可忽略项或完全干净。

### Task L2：Redis 集群路径补 TLS（本地合并版硬化）

**文件**：`internal/container/container.go`、`internal/router/task.go`（对照上游 `common.RedisTLSConfig()`）。

- 单机与集群的 go-redis / asynq 连接均设置 `TLSConfig`  
- 行为：`REDIS_USE_TLS` 未开时仍为 `nil`（明文）

**验收**：`go build`；有集群环境时可选做 Ping。

### Task L3：构建与快速回归

```powershell
go build -o server.exe ./cmd/server
cd frontend; npm run type-check; npm run build
# 可选：go test ./internal/middleware/... -count=1
```

按升级清单勾选 P0：CAS 登录、共享 KB、SvgIcon 主题、`REDIS_MODE` 空/单机冒烟。

### Task L4：更新清单勾选 +（可选）打 Tag

- 在 `2026-07-09-WeKnora-slj-v0.3.6-to-v0.6.3升级内容清单.md` 勾选已合并/已验证项  
- 可选：`git tag -a nxin-v0.6.3-merge.1 -m "NXIN local merge on WeKnora v0.6.3"`

### Task L5：闸门打开 → 贡献流程

合并版冻结后，按开源贡献方案开：

1. `contrib/redis-cluster`  
2. `contrib/svg-icon`  
3. `contrib/td-color-tokens`  

从 `upstream/main` 干净移植，不直接推本地合并分支。
