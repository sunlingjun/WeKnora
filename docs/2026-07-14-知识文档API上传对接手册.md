# 知识文档 API 上传对接手册（方案 A）

> 适用范围：通过 HTTP API / Go SDK / CLI，将文档上传到**指定知识库**，无需改动服务端。  
> 权威接口细节见 [docs/api/knowledge.md](./api/knowledge.md)；差异以 Swagger（非 release 模式：`/swagger/index.html`）为准。

---

## 1. 快速上手

1. 在 Web 端注册并登录，于**账户信息**页获取 API Key（形如 `sk-...`）。
2. 确认目标知识库 ID（`kb_id`），且库类型为普通文档库（**非 FAQ 库**）。
3. 调用上传接口 → 拿到 `knowledge.id` → **轮询** `parse_status` 至终态后再做检索。

**最小 curl（本地文件 → 指定 KB）：**

```bash
export HOST="https://zsk.nxin.com"
export API_KEY="sk-xxxxx"
export KB_ID="kb-00000001"

curl -sS -X POST "${HOST}/api/v1/knowledge-bases/${KB_ID}/knowledge/file" \
  -H "X-API-Key: ${API_KEY}" \
  -H "X-Request-ID: req-$(date +%s)" \
  -F "file=@./sample.pdf" \
  -F "channel=api"
```

成功时 `HTTP 200`，响应中的 `data.id` 即为知识 ID；此时 `parse_status` 多为 `pending` / `processing`，**尚未可检索**。

## 2. 基础约定

| 项 | 约定 |
|----|------|
| Base URL | `{host}/api/v1` |
| 鉴权 | 请求头 `X-API-Key: sk-...`（推荐程序化）；或 JWT `Authorization: Bearer <token>` |
| 追踪 | 建议带 `X-Request-ID` |
| KB 定位 | **仅路径参数** `{kb_id}`，不从 header/body 指定知识库 |
| 渠道 | 程序化上传建议 `channel=api`（默认为 `web`） |
| 响应 | 成功多为 `{ "success": true, "data": {...} }` |

**API Key 权限说明**：租户级 API Key 在服务端按租户 Admin 处理，一般可写本租户下有权限的知识库。请妥善保管，勿写入日志或前端仓库。

---

## 3. 上传方式选型

| 场景 | 方法 | 路径 | Content-Type |
|------|------|------|----------------|
| 本地 / 流水线文件 | `POST` | `/knowledge-bases/{kb_id}/knowledge/file` | `multipart/form-data` |
| 公网 URL（网页或远端文件） | `POST` | `/knowledge-bases/{kb_id}/knowledge/url` | `application/json` |
| 纯 Markdown 文本 | `POST` | `/knowledge-bases/{kb_id}/knowledge/manual` | `application/json` |

**不支持走本手册的路径：**

- FAQ 型知识库 → 使用 FAQ 专用导入接口（见 [faq.md](./api/faq.md)）
- 视频文件
- 服务端「一次请求多文件」批量上传（需客户端循环或 CLI `--recursive`）

**常见支持类型**：`pdf`、`txt`、`docx`/`doc`、`md`、`csv`、`xlsx`/`xls`、`pptx`/`ppt`、`json`、`epub`、`mhtml`、常见图片与音频等。  
**大小上限**：受服务端 `MAX_FILE_SIZE_MB` 控制（常见默认约 50MB）。超限返回 400。

## 4. 接口说明与 curl 示例

以下示例统一使用环境变量：`HOST`、`API_KEY`、`KB_ID`。

### 4.1 上传本地文件

**表单字段**

| 字段 | 必填 | 说明 |
|------|------|------|
| `file` | 是 | 文件本体 |
| `fileName` | 否 | 自定义名；文件夹上传可用相对路径如 `docs/intro.md` |
| `metadata` | 否 | JSON 字符串，`map[string]string`，便于业务对账 |
| `enable_multimodel` | 否 | `"true"` / `"false"` |
| `process_config` | 否 | JSON，批次解析配置覆盖 |
| `tag_ids` | 否 | 标签 ID，**逗号分隔**（实现字段；部分旧文档写 `tag_id`） |
| `channel` | 否 | 建议 `api` |

```bash
curl -sS -X POST "${HOST}/api/v1/knowledge-bases/${KB_ID}/knowledge/file" \
  -H "X-API-Key: ${API_KEY}" \
  -F "file=@./sample.pdf" \
  -F "channel=api" \
  -F 'metadata={"source":"erp","biz_id":"PO-10086"}' \
  -F "enable_multimodel=false"
```

> 使用 `-F` 时不要再手动设置 `Content-Type: application/json`，否则 multipart 会解析失败。

**成功响应要点**

- HTTP `200`
- `data.id`：知识 ID（后续轮询用）
- `data.parse_status`：通常为 `pending` 或 `processing`
- `data.enable_status`：解析完成前常为 `disabled`

### 4.2 从 URL 创建

规则简述：

- 带已知扩展名，或显式传 `file_name` / `file_type` → **远端文件下载**
- 否则 → **网页抓取**
- URL 经 SSRF 校验，禁止指向内网/回环

**网页抓取：**

```bash
curl -sS -X POST "${HOST}/api/v1/knowledge-bases/${KB_ID}/knowledge/url" \
  -H "X-API-Key: ${API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://github.com/Tencent/WeKnora",
    "channel": "api",
    "enable_multimodel": false
  }'
```

**远端 PDF：**

```bash
curl -sS -X POST "${HOST}/api/v1/knowledge-bases/${KB_ID}/knowledge/url" \
  -H "X-API-Key: ${API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/papers/whitepaper.pdf",
    "file_name": "whitepaper.pdf",
    "file_type": "pdf",
    "channel": "api"
  }'
```

成功一般为 HTTP `201`。

### 4.3 手工 Markdown

```bash
curl -sS -X POST "${HOST}/api/v1/knowledge-bases/${KB_ID}/knowledge/manual" \
  -H "X-API-Key: ${API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "产品使用指南",
    "content": "# 产品使用指南\n\n## 快速入门\n\n正文...",
    "channel": "api",
    "status": "published"
  }'
```

`status=draft` 时通常不触发解析（以服务端实际行为为准）。成功一般为 HTTP `200`。

### 4.4 查询状态（轮询必用）

```bash
KNOWLEDGE_ID="4c4e7c1a-09cf-485b-a7b5-24b8cdc5acf5"

curl -sS "${HOST}/api/v1/knowledge/${KNOWLEDGE_ID}" \
  -H "X-API-Key: ${API_KEY}"
```

关注字段：

| 字段 | 说明 |
|------|------|
| `parse_status` | 解析流水线状态 |
| `error_message` | 失败原因 |
| `enable_status` | `enabled` / `disabled` |

深度排查：`GET /api/v1/knowledge/{id}/stages`（及 `/spans`）。

失败后可：`POST /api/v1/knowledge/{id}/reparse`；进行中可：`POST /api/v1/knowledge/{id}/cancel-parse`。

## 5. 解析状态机与轮询约定

```
pending → processing → finalizing → completed
                                 ↘ failed
                 （任意进行中态）→ cancelled
```

| 状态 | 含义 | 对接方动作 |
|------|------|------------|
| `pending` | 已落库，等待入队/调度 | 继续轮询 |
| `processing` | 解析 / 分块 / 向量化 | 继续轮询 |
| `finalizing` | 主解析结束，摘要/图谱等后处理中 | 继续轮询；若只需基础检索可再观察是否已可搜 |
| `completed` | 全部成功 | **停止轮询，可检索** |
| `failed` | 失败 | 读 `error_message`；可 reparse 或上报 |
| `cancelled` | 用户取消 | 可 reparse |

**推荐轮询策略**

| 项 | 建议 |
|----|------|
| 首次间隔 | 2s |
| 退避 | 指数退避，上限 15s |
| 超时 | 按文件大小自定（如普通 PDF 5–15 分钟；大文件/多模态更长） |
| 终态 | `completed` / `failed` / `cancelled` |

**bash 轮询示例：**

```bash
KNOWLEDGE_ID="..."
interval=2
for i in $(seq 1 60); do
  status=$(curl -sS "${HOST}/api/v1/knowledge/${KNOWLEDGE_ID}" \
    -H "X-API-Key: ${API_KEY}" | jq -r '.data.parse_status')
  echo "[$i] parse_status=$status"
  case "$status" in
    completed|failed|cancelled) break ;;
  esac
  sleep "$interval"
  interval=$(( interval < 15 ? interval + 2 : 15 ))
done
```

CLI 等价：

```bash
weknora doc wait "${KNOWLEDGE_ID}" --kb "${KB_ID}"
```

## 6. Go SDK 示例

模块：`github.com/Tencent/WeKnora/client`（仓库内 `client/` 包）。

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"os"
	"time"

	"github.com/Tencent/WeKnora/client"
)

func main() {
	baseURL := envOr("WEKNORA_BASE_URL", "http://localhost:8080")
	apiKey := os.Getenv("WEKNORA_API_KEY")
	kbID := os.Getenv("WEKNORA_KB_ID")
	filePath := envOr("FILE_PATH", "./sample.pdf")

	cli := client.NewClient(baseURL, client.WithAPIKey(apiKey))
	ctx := context.Background()

	meta := map[string]string{
		"source": "api",
		"biz_id": "PO-10086",
	}
	enableMM := false

	k, err := cli.CreateKnowledgeFromFile(
		ctx, kbID, filePath, meta, &enableMM, "", "api", nil,
	)
	if err != nil {
		if errors.Is(err, client.ErrDuplicateFile) {
			// 409：同库已存在；SDK 会返回已有条目（视版本而定）
			fmt.Printf("duplicate file, existing id may be usable: %v\n", err)
			return
		}
		panic(err)
	}
	fmt.Printf("uploaded: id=%s parse_status=%s\n", k.ID, k.ParseStatus)

	// 轮询至终态
	deadline := time.Now().Add(15 * time.Minute)
	interval := 2 * time.Second
	for time.Now().Before(deadline) {
		cur, err := cli.GetKnowledge(ctx, k.ID)
		if err != nil {
			panic(err)
		}
		fmt.Printf("parse_status=%s\n", cur.ParseStatus)
		switch cur.ParseStatus {
		case "completed":
			fmt.Println("ready for retrieval")
			return
		case "failed", "cancelled":
			fmt.Printf("terminal: %s err=%s\n", cur.ParseStatus, cur.ErrorMessage)
			return
		}
		time.Sleep(interval)
		if interval < 15*time.Second {
			interval += 2 * time.Second
		}
	}
	panic("wait timeout")
}

func envOr(k, def string) string {
	if v := os.Getenv(k); v != "" {
		return v
	}
	return def
}
```

**URL / Manual：**

```go
// URL（网页或远端文件）
urlReq := client.CreateKnowledgeFromURLRequest{
	URL:     "https://example.com/a.pdf",
	FileName: "a.pdf",
	FileType: "pdf",
	Channel: "api",
}
k, err := cli.CreateKnowledgeFromURL(ctx, kbID, urlReq)

// Manual Markdown
k, err = cli.CreateManualKnowledge(ctx, kbID, &client.CreateManualKnowledgeRequest{
	Title:   "产品使用指南",
	Content: "# 标题\n\n正文",
	Channel: "api",
})
```

**CLI 备选（零代码）：**

```bash
export WEKNORA_KB_ID="kb-00000001"
weknora auth login   # 或配置 profile / API Key
weknora doc upload ./sample.pdf --kb "${WEKNORA_KB_ID}"
weknora doc wait <knowledge_id>

weknora doc create --text "# hello" --title "手册" --kb "${WEKNORA_KB_ID}"
```

## 7. 错误码约定

### 7.1 通用错误信封（AppError）

除「文件/URL 重复」外，多数失败走中间件统一格式：

```json
{
  "success": false,
  "error": {
    "code": 1000,
    "message": "错误信息",
    "details": "可选详情"
  }
}
```

| HTTP | `error.code` | 常量含义 | 典型 message / 场景 | 对接建议 |
|------|--------------|----------|---------------------|----------|
| 400 | `1000` | BadRequest | 缺文件、超大小（`文件大小不能超过 N MB`）、metadata/process_config JSON 非法、URL SSRF 等 | **不重试**；修正参数后重发 |
| 401 | `1001` | Unauthorized | 缺少/错误 API Key 或 Token | 检查密钥；**不盲目重试** |
| 403 | `1002` | Forbidden | 无 KB 写权限、跨租户被拒 | 换有权限的 KB/密钥；**不重试** |
| 404 | `1003` | NotFound | KB / Knowledge 不存在 | 核对 ID；**不重试** |
| 409 | `1005`* | Conflict | 通用冲突（较少见于上传主路径） | 见 7.2 |
| 503 | `1008` | ServiceUnavailable | 权限校验暂时不可用等 | **可退避重试** |
| 500 | `1006` 等 | InternalServer | 服务内部错误 | **有限次退避重试**；仍失败则告警 |

\* 数值以 `internal/errors` 为准；对接方应同时看 **HTTP 状态码** 与 `message`。

### 7.2 上传去重类型（特殊 409，非 AppError 信封）

同库重复文件或 URL 时，handler 直接返回：

```json
{
  "success": false,
  "message": "...",
  "code": "duplicate_file",
  "data": { "...已存在的 Knowledge 对象..." }
}
```

| HTTP | `code`（字符串） | 说明 | 对接建议 |
|------|------------------|------|----------|
| 409 | `duplicate_file` | 同库文件 hash/名等冲突 | **视为幂等成功**：使用 `data.id` 继续轮询/业务关联，勿当硬失败 |
| 409 | `duplicate_url` | 同库 URL 冲突 | 同上 |

Go SDK：`ErrDuplicateFile` / `ErrDuplicateURL`。

### 7.3 对接侧决策简表

| 情况 | 是否重试上传 | 备注 |
|------|--------------|------|
| 网络超时 / 5xx / 503 | 是（指数退避，限次） | 注意是否已成功创建（可用列表/去重 409 判断） |
| 400 参数错误 | 否 | 修参 |
| 401 / 403 | 否 | 修凭证或权限 |
| 409 duplicate_* | 否（当作已存在） | 用返回的 `data` |
| 上传成功但 `parse_status=failed` | 不重传同内容；可 `reparse` | 先读 `error_message` |

## 8. 对接检查清单

- [ ] 已拿到 `API_KEY` 与正确 `KB_ID`（非 FAQ）
- [ ] 文件类型与大小在允许范围内
- [ ] 上传后保存 `knowledge.id`，并实现轮询至终态
- [ ] `channel=api` + `metadata` 写入业务主键，便于对账
- [ ] 处理 `duplicate_file` / `duplicate_url` 为幂等
- [ ] 密钥不落日志；生产使用 HTTPS
- [ ] 大批量：客户端控制并发（建议低并发串行/小队列），避免打满解析队列

## 10. 已知限制（对接知悉）

1. **异步解析**：创建成功 ≠ 可检索，必须轮询或 `doc wait`。
2. **无服务端多文件 batch**：批量请循环调用；CLI 可用 `--recursive`。
3. **标签字段**：服务端文件上传表单为 `tag_ids`（逗号分隔）；部分文档/SDK 仍使用 `tag_id`，标签绑定前请先实测。
4. **URL 不可达内网**：SSRF 防护会拒绝私网地址。
5. **视频不支持**；图片/音频依赖环境是否配置对象存储与 VLM/ASR。
