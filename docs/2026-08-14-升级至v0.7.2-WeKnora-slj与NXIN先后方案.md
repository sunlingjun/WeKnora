### 2.3 结构变更（冲突主因）

- **`internal/router/router.go` 按域拆分**：`routes_agent.go`、`routes_auth_tenant.go`、`routes_chat.go`、`routes_infra.go`、`routes_knowledge.go`、`files.go`、`static.go`。官方 `router.go` 从 ~2165 行降到 ~268 行。
- **Auth 中间件拆分**：新增 `auth_context.go`，session context 统一挂载；官方 `Auth()` 参数集与 slj 定制（`CASAuthService` + `UniversalClient`）**不一致**。
- **`modelcontext` 合并**：`llmreference` / `llmresource` 收口；可能碰到引用图 / handle 编解码。
- **前端 i18n 按 `zh-CN` 裁剪** + `localeKeyAudit`：自研键必须留在 `zh-CN.ts`，否则其它语言 CI 会丢键。
- **注册密码不再 Sanitize 后再 hash**（修特殊字符密码被破坏）。CAS 本地密码工具若仍走同一路径，合完后核对。

### 3.2 冲突时「重新挂回」，不是「选一边」

官方拆路由后，NXIN 函数往往还在旧 `router.go` 里，而官方已把调用点拆走。解冲突口诀：

```
官方把 router.go 拆成多文件？
  → 接受官方骨架；把 NXIN 注册点搬到对应新文件，并在 NewRouter 里再挂一次

官方改了 CORS AllowOrigins: ["*"]？
  → 保留 slj AllowOriginFunc + Hostname() 放行 *.nxin.com（含端口）

官方 Auth() 少了 CASAuthService / RedisClient？
  → 保留 slj 参数：tryNXINCASAuth + UniversalClient；接到新的 auth_context 挂载点

官方 files.go 新建？
  → 把 /files 代理迁过去；config.yaml allowed_path_globs 仍含 /files 与 /api/v1/*

官方 RedisClient 类型变回 *redis.Client？
  → 保持 redis.UniversalClient；Cluster 禁止 redis.NewClient(REDIS_ADDR)

出现 /knowledge-bases/:id 吃掉 user|shared？
  → 静态路由写在参数路由前（现应在 routes_knowledge.go）

官方改了 Login / router.beforeEach？
  → 未登录走 casStore.validateSession()，禁止直接 next('/login')

官方 prune i18n？
  → zh-CN 保留 ZSK / members / 农信导入 / MCP 复制配置等自研键；再同步其它 locale
  → 必须保留 sharedKbSquare 整树 + knowledgeList.sharedTag/leave/role/sections.joinedShared
  → 合完跑 kbMembersI18n.test.ts 与 sharedKbI18n.test.ts（勿只信 localeKeyAudit）

官方改了 Dockerfile / duckdb？
  → GOPROXY 多源、curl 预下载、LOAD-first、legacy builder 兼容

官方改了 compose？
  → 透传 CAS_ENVIRONMENT、CAS_UC_*；https 默认注释（Nginx 终结 TLS）
```
